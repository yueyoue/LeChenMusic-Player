# A. 影视首页 — 最近播放（播放记录）

---

## 1. 功能概述

用户在 APP 端观看影视内容后，播放记录会自动保存到 LunaTV 服务端。首页「最近播放」区域展示这些记录，用户点击可跳转继续播放。

**适用布局：** 手机 UI + 平板 UI 均需支持。

## 3. 数据模型

### 3.1 保存播放记录 — 请求体

```kotlin
// data/model/VideoModels.kt

/**
 * 单条播放记录的 record 部分。
 *
 * ⚠️ 重要：source 和 id 字段必须加 @Transient！
 * LunaTV 服务器的 /api/playrecords POST 接口会拒绝 body 中包含 source/id 的请求，
 * 返回 {"error":"Invalid record data"}。
 * source 和 id 仅用于在 ViewModel 中构造 key 字段，不应序列化到 JSON body。
 */
data class PlayRecordRequest(
    @Transient val source: String = "",   // ← 必须 @Transient
    @Transient val id: String = "",       // ← 必须 @Transient
    val title: String = "",
    val cover: String = "",
    val year: String = "",
    @SerializedName("source_name") val sourceName: String = "",
    val index: Int = 1,
    val total_episodes: Int = 0,
    val play_time: Int = 0,
    val total_time: Int = 0,
    val type: String = ""
)

/**
 * 保存播放记录的完整请求体。
 * key 格式: "source+id"（如 "iqiyizyapi.com+80462"）
 */
data class PlayRecordSaveRequest(
    val key: String,
    val record: PlayRecordRequest
)
```

### 3.2 读取播放记录 — 响应体

```kotlin
/**
 * LunaTV 返回的播放记录（单条）。
 * 注意：服务器返回的 dict key 是 "source+id" 格式，
 * record 中不包含 source 和 id 字段，需要从 key 中解析。
 */
data class VideoPlayRecord(
    @SerializedName("videoId") val videoIdRaw: String = "",
    val source: String = "",
    val title: String = "",
    val cover: String = "",
    val year: String = "",
    val index: Int = 0,
    @SerializedName("episode_index") val episodeIndexAlt: Int = 0,
    val totalEpisodes: Int = 0,
    @SerializedName("total_episodes") val totalEpisodesAlt: Int = 0,
    val playTime: Int = 0,
    @SerializedName("play_time") val playTimeAlt: Int = 0,
    val totalTime: Int = 0,
    @SerializedName("total_time") val totalTimeAlt: Int = 0,
    @SerializedName("save_time") val saveTime: Long = System.currentTimeMillis(),
    val type: String = "",
    @SerializedName("source_name") val sourceName: String = "",
    @SerializedName("search_title") val searchTitle: String = ""
) {
    val displayTotalEpisodes: Int get() = if (totalEpisodes > 0) totalEpisodes else totalEpisodesAlt
    val displayPlayTime: Int get() = if (playTime > 0) playTime else playTimeAlt
    val displayTotalTime: Int get() = if (totalTime > 0) totalTime else totalTimeAlt
    val displayEpisodeIndex: Int get() = if (index > 0) index else episodeIndexAlt
    val progressPercent: Float
        get() = if (displayTotalTime > 0) (displayPlayTime.toFloat() / displayTotalTime).coerceIn(0f, 1f) else 0f
}
```

## 4. API 接口

### 4.1 保存播放记录

```
POST /api/playrecords
Content-Type: application/json

请求体:
{
    "key": "iqiyizyapi.com+80462",
    "record": {
        "title": "森中有林",
        "cover": "https://...",
        "year": "2026",
        "source_name": "🎬-爱奇艺-",
        "index": 1,
        "total_episodes": 32,
        "play_time": 120,
        "total_time": 2330,
        "type": "tv"
    }
}

响应: {"success": true}
```

**⚠️ 注意事项：**
- `record` 中**不能包含 `source` 和 `id` 字段**，否则服务器返回 `{"error":"Invalid record data"}`
- `source` 和 `id` 信息通过 `key` 字段传递（格式: `"source+id"`）
- `save_time` 不需要客户端传，服务器会自动添加
- `search_title` 可选

### 4.2 读取播放记录

```
GET /api/playrecords

响应: {
    "iqiyizyapi.com+80462": {
        "title": "森中有林",
        "source_name": "🎬-爱奇艺-",
        "year": "2026",
        "cover": "https://...",
        "index": 1,
        "total_episodes": 32,
        "play_time": 120,
        "total_time": 2330,
        "save_time": 1784897837938,
        "original_episodes": 32
    },
    ...
}
```

**⚠️ 注意事项：**
- 返回的是 **dict（键值对）**，不是 list
- key 格式为 `"source+id"`，需要客户端解析出 source 和 id
- `source` 和 `id` 不在 record value 中，需要从 key 拆分

### 4.3 Retrofit 接口定义

```kotlin
// data/api/VideoApiClient.kt

interface LunaTvApi {
    /** 返回 dict: {"source+id": {record...}} */
    @GET("api/playrecords")
    suspend fun getPlayRecords(): Response<Map<String, VideoPlayRecord>>

    @POST("api/playrecords")
    suspend fun savePlayRecord(@Body request: PlayRecordSaveRequest): Response<Map<String, Any>>
}
```

## 5. ViewModel 层

### 5.1 读取播放记录

```kotlin
// ui/VideoViewModel.kt

private val _playRecords = MutableStateFlow<List<VideoPlayRecord>>(emptyList())
val playRecords: StateFlow<List<VideoPlayRecord>> = _playRecords.asStateFlow()

fun loadPlayRecords() {
    viewModelScope.launch {
        try {
            val api = VideoApiClient.getApi(videoServerUrl.value)
            val response = withContext(Dispatchers.IO) { api.getPlayRecords() }
            if (response.isSuccessful && response.body() != null) {
                // LunaTV 返回 dict: {"source+id": record}
                val dict = response.body()!!
                val records = dict.entries.mapNotNull { (key, record) ->
                    // 从 key 中提取 source 和 id (格式: "source+id")
                    val parts = key.split("+", limit = 2)
                    val source = parts.getOrElse(0) { "" }
                    val videoId = parts.getOrElse(1) { key }
                    record.copy(
                        videoIdRaw = videoId,
                        source = source
                    )
                }.sortedByDescending { it.saveTime }
                _playRecords.value = records
            }
        } catch (_: Exception) { }
    }
}
```

### 5.2 保存播放记录

```kotlin
// ui/VideoViewModel.kt

fun savePlayRecord(record: PlayRecordRequest) {
    viewModelScope.launch {
        try {
            val api = VideoApiClient.getApi(videoServerUrl.value)
            val key = "${record.source}+${record.id}"
            val request = PlayRecordSaveRequest(key = key, record = record)
            withContext(Dispatchers.IO) { api.savePlayRecord(request) }
        } catch (_: Exception) { }
    }
}
```

## 6. UI 层 — 保存播放记录

**手机 UI 和平板 UI 的影视详情页都必须实现以下两个保存时机：**

### 6.1 定期保存（每 10 秒）

```kotlin
// 在影视详情页 Composable 中

// ⚠️ 必须提前声明 selectedEpisode，不能在后面重复声明
var selectedEpisode by remember { mutableIntStateOf(0) }

LaunchedEffect(video) {
    while (true) {
        kotlinx.coroutines.delay(10000)
        if (exoPlayer.isPlaying && exoPlayer.duration > 0) {
            viewModel.savePlayRecord(
                PlayRecordRequest(
                    source = video.source,
                    id = video.id,
                    title = video.title,
                    cover = video.displayCover,
                    year = video.year,
                    sourceName = video.displaySourceName,
                    index = selectedEpisode + 1,
                    total_episodes = video.episodes.size,
                    play_time = (exoPlayer.currentPosition / 1000).toInt(),
                    total_time = (exoPlayer.duration / 1000).toInt(),
                    type = video.typeName
                )
            )
        }
    }
}
```

### 6.2 退出时保存

```kotlin
DisposableEffect(Unit) {
    onDispose {
        // 退出时保存播放记录
        if (exoPlayer.currentPosition > 1000) {
            viewModel.savePlayRecord(
                PlayRecordRequest(
                    source = video.source,
                    id = video.id,
                    title = video.title,
                    cover = video.displayCover,
                    year = video.year,
                    sourceName = video.displaySourceName,
                    index = selectedEpisode + 1,
                    total_episodes = video.episodes.size,
                    play_time = (exoPlayer.currentPosition / 1000).toInt(),
                    total_time = (exoPlayer.duration / 1000).toInt(),
                    type = video.typeName
                )
            )
        }
        exoPlayer.stop()
        exoPlayer.release()
    }
}
```

## 9. 常见踩坑点

### ❌ 踩坑 1：`record` body 中包含 `source` 和 `id`

**现象：** 保存播放记录时服务器返回 `{"error":"Invalid record data"}`，记录保存失败。

**原因：** `PlayRecordRequest` 的 `source` 和 `id` 字段没有加 `@Transient` 注解，Gson 序列化时会把它们包含在 JSON body 中，但 LunaTV 服务器不接受这两个字段。

**修复：**
```kotlin
data class PlayRecordRequest(
    @Transient val source: String = "",   // ← 必须加 @Transient
    @Transient val id: String = "",       // ← 必须加 @Transient
    // ... 其他字段
)
```

**验证方法：** 用 curl 测试：
```bash
# ❌ 错误 — record 中含 source+id
curl -X POST "http://服务器/api/playrecords" \
  -H "Content-Type: application/json" \
  -d '{"key":"src+123","record":{"source":"src","id":"123","title":"test"}}'
# → {"error":"Invalid record data"}

# ✅ 正确 — record 中不含 source+id
curl -X POST "http://服务器/api/playrecords" \
  -H "Content-Type: application/json" \
  -d '{"key":"src+123","record":{"title":"test","play_time":60,"total_time":3600}}'
# → {"success":true}
```

### ❌ 踩坑 2：平板 UI 返回首页后看不到最新记录

**现象：** 手机 UI 正常，平板 UI 播放后返回首页看不到刚看的影片，需要重启 APP 才出现。

**原因：** 平板的 `TabletVideoDetailScreen` 的 `onBack` 回调直接调用 `onBack()`（即 `navController.popBackStack()`），没有先刷新播放记录。虽然 `MainActivity` 中有 `LaunchedEffect(currentRoute)` 监听路由变化并刷新，但存在时序问题——`onDispose` 中的保存是异步的，`loadPlayRecords()` 可能在保存完成前就执行了。

**修复：** 在平板的 `onBack` 中**先刷新再返回**：
```kotlin
// MainActivity.kt
TabletVideoDetailScreen(
    onBack = {
        videoViewModel.loadPlayRecords()  // ← 先刷新
        onBack()                          // ← 再返回
    },
)
```

### ❌ 踩坑 3：平板详情页没有保存播放记录的代码

**现象：** 平板播放影视后，web 端看不到播放记录。

**原因：** `TabletVideoDetailScreen` 中完全没有播放记录保存逻辑（遗漏）。手机的 `VideoDetailScreen` 有定期保存和退出保存，但平板版本没有同步。

**修复：** 在 `TabletVideoDetailScreen` 中添加与手机 `VideoDetailScreen` 相同的保存逻辑（见第 6 节）。

### ❌ 踩坑 4：`selectedEpisode` 重复声明导致编译错误

**现象：** `Variable 'selectedEpisode' must be initialized` 编译错误。

**原因：** 在添加播放记录保存代码时，提前声明了 `var selectedEpisode by remember { mutableIntStateOf(0) }`，但后面原有的代码又声明了一次同名变量。

**修复：** 只保留一个声明，删除重复的：
```kotlin
// ✅ 在播放记录保存代码前声明一次
var selectedEpisode by remember { mutableIntStateOf(0) }

// ... 播放记录保存代码使用 selectedEpisode ...

// ❌ 删除这里的重复声明
// var selectedEpisode by remember { mutableIntStateOf(0) }
```

## 11. 功能概述

用户在首页点击影片后，APP 需要：
1. 调用 LunaTV `/api/detail` 获取该源的详情
2. 如果该源无播放资源，自动调用 `/api/search` 搜索其他源
3. 将所有可用源展示给用户（手机：横向 Chip + 弹窗列表；平板：右侧 Tab 列表）
4. 用户可切换源，切换后从上次播放位置继续播放
5. 用户可对源进行测速，按响应速度排序

## 13. 数据模型

### 13.1 VideoDetail（影片详情）

```kotlin
data class VideoDetail(
    val id: String = "",
    val title: String = "",
    val year: String = "",
    val cover: String = "",
    @SerializedName("poster") val poster: String = "",
    val desc: String = "",
    val type: String = "",
    @SerializedName("type_name") val typeName: String = "",
    val rate: String? = null,
    val director: String = "",
    val actor: String = "",
    val area: String = "",
    // episodes: 当前源的播放地址列表
    val episodes: List<String> = emptyList(),
    @SerializedName("episodes_titles") val episodesTitles: List<String> = emptyList(),
    // sources: 该影片在 LunaTV 中所有可用源（如果 LunaTV 支持）
    val sources: List<VideoSource> = emptyList(),
    // ... 其他字段
) {
    /** 将 episodes URL 列表转换为 VideoSource/VideoEpisode 结构 */
    fun toSources(): List<VideoSource> {
        if (sources.isNotEmpty()) return sources
        if (episodes.isEmpty()) return emptyList()
        val eps = episodes.mapIndexed { index, url ->
            val title = episodesTitles.getOrNull(index) ?: "第${index + 1}集"
            VideoEpisode(index = index, title = title, url = url)
        }
        return listOf(VideoSource(
            sourceName = displaySourceName.ifBlank { "默认" },
            source = source,
            episodes = eps
        ))
    }
}
```

## 14. API 接口

### 14.1 获取影片详情

```
GET /api/detail?source=iqiyizyapi.com&id=80462

响应（裸 JSON，无 code/msg 包装）:
{
    "id": "80462",
    "title": "森中有林",
    "year": "2026",
    "source": "iqiyizyapi.com",
    "source_name": "🎬-爱奇艺-",
    "episodes": ["https://xxx.m3u8", ...],
    "episodes_titles": ["1", "2", ...],
    "sources": [...],
    ...
}
```

**⚠️ 注意事项：**
- 响应是裸 JSON 对象，没有 `code`/`msg` 包装

## 15. ViewModel 层 — 核心逻辑

### 15.1 loadDetail() — 加载影片详情

```kotlin
fun loadDetail(source: String, id: String) {
    if (source.isBlank() || id.isBlank()) {
        _toastMessage.value = "参数错误"
        return
    }
    // 避免重复加载（已有完整数据时跳过）
    val existing = _videoDetail.value
    if (existing != null && existing.source == source && existing.id == id
        && (existing.episodes.isNotEmpty() || existing.sources.isNotEmpty())) {
        _detailLoading.value = false
        return
    }
    viewModelScope.launch {
        _detailLoading.value = true
        try {
            val api = VideoApiClient.getApi(videoServerUrl.value)
            val response = withContext(Dispatchers.IO) { api.getDetail(source, id) }
            if (response.isSuccessful && response.body() != null) {
                val detail = response.body()!!
                // 如果该源无资源，自动搜索其他源
                if (detail.episodes.isEmpty() && detail.sources.isEmpty()) {
                    _toastMessage.value = "该源暂无播放资源，正在尝试其他源..."
                    if (detail.title.isNotBlank()) {
                        searchAndPlay(detail.title, detail.doubanId, detail.year)
                        return@launch
                    }
                }
                _videoDetail.value = detail
            }
        } catch (e: Exception) {
            _toastMessage.value = "加载详情失败: ${e.message}"
        } finally {
            _detailLoading.value = false
        }
    }
}
```

### 15.2 searchAndPlay() — 搜索播放源并选择最佳匹配

```kotlin
fun searchAndPlay(title: String, doubanId: String, year: String = "") {
    viewModelScope.launch {
        _searchSourceLoading.value = true
        _detailLoading.value = true
        try {
            val api = VideoApiClient.getApi(videoServerUrl.value)
            val searchResp = withContext(Dispatchers.IO) { api.search(title) }
            val results = searchResp.body()?.results ?: emptyList()

            // 保存所有有 episodes 的源（去重，每个 source 只取第一个）
            val validSources = results.filter { it.episodes.isNotEmpty() }
                .groupBy { it.source }
                .values.map { group -> group.first() }
                .take(30)
            _allSearchSources.value = validSources  // ← 关键：保存到全局状态

            // 四级匹配选择最佳源
            val normalizedTitle = title.replace(" ", "").lowercase()

            // 第一级: 标题精确匹配 + 年份匹配
            var matched = validSources.firstOrNull { src ->
                src.title.replace(" ", "").lowercase() == normalizedTitle
                && (year.isBlank() || src.year.lowercase() == year.lowercase())
            }
            // 第二级: 标题包含匹配 + 年份匹配
            if (matched == null) {
                matched = validSources.firstOrNull { src ->
                    val srcTitle = src.title.replace(" ", "").lowercase()
                    (srcTitle.contains(normalizedTitle) || normalizedTitle.contains(srcTitle))
                    && (year.isBlank() || src.year.lowercase() == year.lowercase())
                }
            }
            // 第三级: 标题精确匹配（忽略年份）
            if (matched == null) {
                matched = validSources.firstOrNull {
                    it.title.replace(" ", "").lowercase() == normalizedTitle
                }
            }
            // 第四级: 取第一个有效源
            if (matched == null) matched = validSources.firstOrNull()

            // 构造 VideoDetail 并导航到详情页
            if (matched != null && matched.episodes.isNotEmpty()) {
                _videoDetail.value = VideoDetail(/* 从 matched 构造 */)
                _navigateToDetail.value = true
            }
        } finally {
            _searchSourceMessage.value = ""
        }
    }
}
```

### 15.4 testSourceSpeeds() — 源测速

```kotlin
private val _sourceSpeeds = MutableStateFlow<Map<String, Long>>(emptyMap())
val sourceSpeeds: StateFlow<Map<String, Long>> = _sourceSpeeds.asStateFlow()
private val _speedTesting = MutableStateFlow(false)
val speedTesting: StateFlow<Boolean> = _speedTesting.asStateFlow()

fun testSourceSpeeds() {
    val sources = _allSearchSources.value
    if (sources.isEmpty()) return
    viewModelScope.launch {
        _speedTesting.value = true
        val speeds = mutableMapOf<String, Long>()
        val client = okhttp3.OkHttpClient.Builder()
            .connectTimeout(5, java.util.concurrent.TimeUnit.SECONDS)
            .readTimeout(5, java.util.concurrent.TimeUnit.SECONDS)
            .build()

        sources.forEach { source ->
            val url = source.episodes.firstOrNull()
            if (url != null && url.isNotBlank()) {
                val ping = withContext(Dispatchers.IO) {
                    try {
                        val start = System.currentTimeMillis()
                        val request = okhttp3.Request.Builder().url(url).head().build()
                        client.newCall(request).execute().use { _ -> }
                        System.currentTimeMillis() - start
                    } catch (_: Exception) { -1L }
                }
                speeds[source.source] = ping
                _sourceSpeeds.value = speeds.toMap()  // 实时更新 UI
            }
        }
        _speedTesting.value = false
        // 按速度排序（快的在前，超时排最后）
        _allSearchSources.value = sources.sortedBy { speeds[it.source] ?: Long.MAX_VALUE }
    }
}
```

### 16.2 切换源 — 保存播放位置（关键！）

切换源时必须：
1. 先保存当前播放位置
2. 设置 `isSwitchingSource = true`（防止 `LaunchedEffect(video)` 重置播放）
3. 停止当前播放 → 加载新源 → 恢复播放位置

```kotlin
// TabletVideoDetailScreen.kt

// ⚠️ 必须在外部声明，不能在 Composable 内重复声明
var isSwitchingSource by remember { mutableStateOf(false) }

// 监听 video 变化自动播放第一集
// ⚠️ 切换源时必须跳过！否则会重置播放位置
LaunchedEffect(video) {
    if (isSwitchingSource) {
        isSwitchingSource = false  // 消费标记
        return@LaunchedEffect
    }
    val src = video.toSources().firstOrNull()
    val ep = src?.episodes?.getOrNull(0)
    if (ep != null && ep.url.isNotBlank()) {
        exoPlayer.setMediaItem(MediaItem.fromUri(ep.url))
        exoPlayer.prepare()
        exoPlayer.playWhenReady = true
    }
}

// 源列表的 onSourceSelect 回调
onSourceSelect = { index, info ->
    // 1. 保存当前位置
    val savedPosition = exoPlayer.currentPosition.coerceAtLeast(0L)
    // 2. 设置切换标记
    isSwitchingSource = true
    // 3. 更新 UI 状态
    selectedSource = index
    selectedEpisode = 0
    // 4. 切换源（更新 videoDetail）
    viewModel.switchSource(info)
    // 5. 加载新源并恢复位置
    val ep = info.episodes.firstOrNull()
    if (ep != null && ep.isNotBlank()) {
        exoPlayer.stop()
        exoPlayer.setMediaItem(MediaItem.fromUri(ep))
        exoPlayer.prepare()
        exoPlayer.playWhenReady = true
        if (savedPosition > 0) {
            exoPlayer.addListener(object : Player.Listener {
                override fun onPlaybackStateChanged(state: Int) {
                    if (state == Player.STATE_READY) {
                        exoPlayer.seekTo(savedPosition)
                        exoPlayer.removeListener(this)
                    }
                }
            })
        }
    }
}
```

## 18. 常见踩坑点

### ❌ 踩坑 5：平板 UI 显示所有影片的源（每个影片都显示 20 个源）

**现象：** 平板影视详情页的播放源 Tab 显示 20 个源，但很多跟当前影片无关。

**原因：** `allSearchSources` 是全局状态，包含上次搜索的所有源。直接用它来展示会导致不相关的源也显示出来。

**修复：** 必须按当前影片标题过滤：
```kotlin
val relevantSources = allSearchSources.filter { src ->
    val srcTitle = src.title.replace(" ", "").lowercase()
    srcTitle == normalizedTitle
        || srcTitle.contains(normalizedTitle)
        || normalizedTitle.contains(srcTitle)
}
```

### ❌ 踩坑 6：切换源后从头播放（不记住播放位置）

**现象：** 切换播放源后，视频从第一集开头播放，不继续之前的位置。

**原因：** `LaunchedEffect(video)` 在 `switchSource()` 更新 `_videoDetail` 后触发，重置播放器到第一集开头，覆盖了 seekTo 的位置恢复。

**修复：** 添加 `isSwitchingSource` 标志，切换源时跳过 `LaunchedEffect(video)` 的自动播放：
```kotlin
var isSwitchingSource by remember { mutableStateOf(false) }

LaunchedEffect(video) {
    if (isSwitchingSource) {
        isSwitchingSource = false
        return@LaunchedEffect  // ← 跳过自动播放
    }
    // ... 正常自动播放逻辑
}
```

### ❌ 踩坑 7：源测速没有实时更新

**现象：** 点击测速后，所有源同时显示结果，而不是逐个显示。

**原因：** `_sourceSpeeds.value` 只在所有测速完成后更新一次。

**修复：** 每测完一个源就更新一次：
```kotlin
sources.forEach { source ->
    val ping = withContext(Dispatchers.IO) { /* 测速 */ }
    speeds[source.source] = ping
    _sourceSpeeds.value = speeds.toMap()  // ← 每次都更新，UI 实时刷新
}
```

### ❌ 踩坑 8：搜索结果为空时没有回退逻辑

**现象：** 点击豆瓣推荐的影片，提示「未找到播放源」。

**原因：** 豆瓣推荐的影片标题可能与 LunaTV 中的标题不完全一致，直接搜索可能匹配不到。

**已有的回退机制：**
1. `loadDetail()` 无资源时自动调用 `searchAndPlay()`
2. `searchAndPlay()` 有四级匹配策略
3. 最终兜底取第一个有效源
